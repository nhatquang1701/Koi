# Koi Engine v1.1.5

Released 2026-10-30. This is the first release that ships the NNUE evaluator as
the only evaluator: the classical (HCE) evaluator was removed, and release
packages now bundle the gated network at `nnue/koi.nnue`.

## Highlights

- **NNUE required, gated network bundled.** The promoted h128 network
  (`koi-v7-h128-official-20261025`, halfka 9216 inputs, 128 hidden, 8 output
  buckets) ships inside every archive and is auto-discovered at boot. Without a
  usable network the engine exits with code 4 and a clear diagnostic;
  `KOI_NNUE_PATH` and `EvalFile` still override the boot choice. The classical
  evaluator and its tuning tools were removed (a clean rewrite is planned).
- **Large x86-64 speed fix.** CPU feature detection (CPUID/XGETBV) used to run
  inside the NNUE evaluation hot path; caching it once per process raised NNUE
  throughput about 5.2x (~100k to ~524k NPS) and measured **+281.7 Elo** in a
  128-game equal-time gate. Apple Silicon was not affected.
- **Fixed-time iteration guard (+56.8 Elo).** A completed deeper iteration is now
  published and used under the fixed-time budget instead of being thrown away;
  a 1+0 confirmation measured +48.0 Elo (LLR 0.942).
- **Full movetime budget (+31 to +42 Elo).** A direct `go movetime N` request now
  spends the full N milliseconds (200 ms becomes ~190 ms instead of ~162 ms);
  clock-play allocation is unchanged.
- **Time-management safety.** The session-level ponderhit stop timer, dynamic
  move overhead, and the clock-mode hard-budget caps remove the online
  time-loss failure mode: a 1+0 self-play probe finished 24/24 games with
  clean shutdowns and **zero time forfeits**, and the live Lichess bot had no
  forfeits in its post-upgrade games.
- **Search constants recalibrated to the pinned NNUE baseline.** Comments and
  measurement tooling now describe the NNUE era (the classical evaluator is
  gone); several search experiments were tested and rejected during the cycle
  and are documented in the evidence reports.

## Strength

- Mac arm64 fixed-time ladder (SF19 `UCI_Elo` anchors, 200 ms, Threads 4,
  Hash 512, promoted network pinned): **~1665 Elo, 95 % CI 1605-1726**.
- Cumulative against the rebuilt program-start baseline:
  - Windows x86-64: +394.5 Elo (LLR 105.8, duplicate-inflated);
  - macOS arm64, duplicate-free: +28.0 Elo (LLR 1.122, positive but under the
    SPRT boundary; the x86-only CPU fix is the difference).
- Deployment delta (old 2026-10-25 shipped binary vs this release, Mac arm64,
  300 duplicate-free 200 ms games): 53.5 %, +24.6 Elo, LLR 0.83.

## Compatibility and upgrade notes

- **A network is required.** Packages include `nnue/koi.nnue`; if you copy the
  executable elsewhere, put the network beside it or set `KOI_NNUE_PATH`.
- The `Speed` option was removed (time allocation always uses 100 %;
  `Slow Mover` remains). Scripts that set it now receive an unknown-option
  diagnostic; behavior is unchanged at full speed.
- The handshake keeps `id name Koi <version>` and adds
  `info string build <commit>`; release archives keep the `koi-engine` file-name
  spelling.
- Optional assets: the CC0 Polyglot book is bundled (`book/koi.bin`), and
  user-supplied Syzygy tablebases are still supported through `SyzygyPath`.

## Assets

- `koi-engine-v1.1.5.zip` (Windows x64)
- `koi-engine-v1.1.5-linux-x86_64.tar.gz`
- `koi-engine-v1.1.5-macos-arm64.tar.gz`
- A `.sha256` sidecar for each archive.

Every archive carries the engine binaries, the promoted network at
`nnue/koi.nnue`, the optional Polyglot book, the installation notes, and a
`package.json` manifest (schema `koi-engine-package-v1`, version `1.1.5`,
per-file SHA-256 hashes, network/book inclusion flags, and source provenance
including the gated-network report hash).

## Known limitations

- The 2600 Elo milestone is not reached; the Mac ladder above is the current
  absolute reference for this release.
- GPU NNUE is experimental, off by default, CUDA-only, and scheduled for
  removal; CPU NNUE is the supported path.
- `UCI_LimitStrength`/`UCI_Elo` are not implemented (external anchors are used
  for measurement); `StrengthMode` remains a compatibility no-op.
- Syzygy tablebase data is not packaged.

## Commits in this release

`git log --oneline 1.1.4..1.1.5` lists the 70+ commits since the previous
release. The largest groups are: the CPUID/NNUE speed fix, the fixed-time
iteration guard and full-movetime budget, the time-management safety work
(session stop timer, dynamic overhead, hard-budget caps), the complete removal
of the classical evaluator and its tooling/tests, the measurement-harness fixes
(per-side boot network, ladder hash bug, duplicate-free 300-opening corpus),
the bot deployment fixes, and the documented search experiments (late-move
pruning, quiescence delta margin, root ordering) that were tested and reverted.
